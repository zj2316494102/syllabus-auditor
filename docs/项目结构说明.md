# syllabus-auditor 项目结构说明

本文档描述 `dev1` 仓库的目录结构、分层职责与模块协作关系，与当前代码保持一致。

## 一、设计原则

| 原则 | 说明 |
|------|------|
| 根目录即项目 | 所有代码与配置位于 `dev1/` 下，对应 Git 仓库 `syllabus-auditor` |
| 可安装 Python 包 | `pyproject.toml` 定义包与 CLI 入口；开发环境 `pip install -e ".[dev]"` |
| 数据库为中心 | 课程库、PDF/MinerU 抽取结果、审核结果、运行记录均持久化到 PostgreSQL |
| 配置分层 | 根目录 `project.yaml`（可调配置）+ `shared/config/schema.py`（领域 schema） |
| 分层清晰 | `application/` 编排流程（CLI 入口），`core/` 抽取与审核引擎，`auditors/` 维度插件 |
| 原始文件本地化 | `data_pdf/` 存放 PDF 等原始文件；`data_md/` 存放 MinerU 输出，均由 `.gitignore` 忽略 |

## 三、根目录文件

## 四、源码包分层说明

### 4.1 入口与 CLI

| 模块 | 作用 |
|------|------|
| `cli.py` | Typer 命令行入口，对外暴露 `init-db`、`prepare *`、`audit run`、`report quality` |
| `application/` | 三条固定语义 Pipeline 的实现，被 CLI 直接调用 |

**职责边界**：`cli.py` 只解析参数并调用 `application/`；不直接处理 SQL 或 PDF 解析。

### 4.2 应用编排层 `application/`

| 子模块 | 入口函数 | 作用 |
|--------|----------|------|
| `prepare/mineru.py` | `run_prepare_mineru` | 读取 `data_md/manifest/index.jsonl`，MinerU MD → 抽取 → `syllabus_extractions` |
| `prepare/pdf.py` | `run_prepare_courses` | 递归扫描 `data_pdf/`，pdfplumber 抽取入库 |
| `prepare/course_library.py` | `run_prepare_course_library` | 课程库 Excel → `courses` |
| `audit/batch.py` | `run_audit_batch` | 按配置维度批审，写入 `audit_*` 表 |
| `report/quality.py` | `run_quality_report` | 生成 `docs/data_quality_report.md` |

### 4.3 审核插件层 `auditors/`

审核维度的插件化扩展点。审核相关配置经 `load_project_config()["audit"]` 读取（合并自 `project.yaml` 与 `schema.py`），与 `registry.py` 对齐。

**六个默认审核维度**（`default_auditors`）：

| key | 类型 | 实现位置 | 说明 |
|-----|------|----------|------|
| `kcjbxxsfykckyz` | rule | `core/audit.py` | 课程基本信息是否与课程库一致 |
| `jxnrsfyxspp` | rule | `core/audit.py` | 教学内容是否与学时匹配 |
| `jxapsfyzcpp` | rule | `core/audit.py` | 教学安排是否与周次匹配 |
| `jxmbnrfsfhyq` | direct_llm | `auditors/jxmbnrfsfhyq.py` | 教学目标、内容、方式是否符合要求 |
| `szysfyxrghj` | direct_llm | `auditors/szysfyxrghj.py` | 是否将思政元素有效融入各环节 |
| `xxyzwzfhmb` | rule | `auditors/xxyzwzfhmb.py` | 信息要素完整、符合模板、是否有中英文简介 |

| 模块 | 作用 |
|------|------|
| `registry.py` | `AuditorSpec` 注册、`validate_audit_config`、LLM 维度调度 |
| `runner.py` | 批量审核：读 DB → 逐门课 `audit_subject` → 写回结果 |

各维度业务规则详见 `docs/` 下对应 Markdown 文档。

### 4.4 核心能力层 `core/`

#### 抽取与 Payload

| 模块 | 作用 |
|------|------|
| `extractors/pdfplumber/` | pdfplumber 表格/文本抽取，含 PyMuPDF 布局增强 |
| `extractors/mineru/` | MinerU MD、middle JSON、表格归一化 |
| `extractors/section_table_parser.py` | 章节表格通用解析 |
| `payload_builder.py` | 原始字段 → 标准 payload（schema 版本见 `PAYLOAD_SCHEMA_VERSION`） |
| `meta_builder.py` | 抽取元数据（来源路径、警告、fallback 等） |
| `quality.py` | 入库前 payload/meta 校验与规范化 |
| `content_layout.py` | 内容布局与章节定位 |

#### 审核引擎

| 模块 | 作用 |
|------|------|
| `audit.py` | 规则类三维审核、课程库匹配、`FieldFinding` / `SectionFinding` 数据结构 |
| `llm.py` | OpenAI 兼容 LLM 客户端，供 direct_llm 维度使用 |

#### 数据库 `core/db/`

| 模块 | 作用 |
|------|------|
| `schema.sql` | 建表 DDL（`init-db` 执行） |
| `connection.py` | 连接池、`get_project_root`、读取 `.env` |
| `init_db.py` | CLI `init-db` 实现 |
| `courses.py` | 课程库读写 |
| `extractions.py` | `syllabus_extractions` 读写 |
| `audit.py` | `audit_runs` / `audit_results` / `audit_findings` / `audit_field_findings` 等 |

### 4.5 共享层 `shared/` 与工具 `utils/`

| 模块 | 作用 |
|------|------|
| `shared/config/__init__.py` | 配置对外入口：`load_project_config()` 等 |
| `shared/config/loader.py` | 合并 `project.yaml` 与 `schema.py` |
| `shared/config/schema.py` | 领域 schema：章节标题、字段映射、审核维度结构 |
| `shared/logging.py` | 结构化日志初始化 |
| `utils/source_verify.py` | 源 PDF/MD 与 payload 字段核对 |
| `utils/llm_protocol.py` | LLM JSON 协议与客户端抽象 |

## 五、数据库表设计

所有业务产物持久化在 PostgreSQL。表结构定义见 `core/db/schema.sql`，详细字段说明见 `docs/*表设计.md`。

| 表名 | 作用 |
|------|------|
| `courses` | 课程库基准数据，来自 Excel 导入 |
| `syllabus_extractions` | PDF/MinerU 抽取的结构化结果（`payload` + `meta` JSONB） |
| `reference_chunks` | 规则库切片（预留 RAG；当前以包内配置与 docs 为主） |
| `audit_runs` | 一次批量审核任务 |
| `audit_results` | 每门课/每套抽取在本次 run 中的总体结论 |
| `audit_findings` | 各审核维度（wd）的 section 级明细 |
| `audit_field_findings` | 字段级审核明细（如课程库比对差异） |
| `audit_artifacts` | 可选调试信息 |
| `audit_run_metrics` | run 级聚合指标 |

**设计要点**：

- 不在磁盘维护独立的 `extracted/`、`reports/` 业务目录；审核结果从 DB 查询
- 质量报告输出到 `docs/data_quality_report.md`（只读已有 DB 产物生成；中间缓存位于 `.cache/quality/`）
- 原始文件保留在 `data_pdf/`、`data_md/`，DB 存路径与结构化结果

## 七、CLI 工作流

安装后可使用 `syllabus-auditor` 命令（等效于 `python -m syllabus_auditor.cli`）。

```bash
# 1. 初始化数据库表结构
syllabus-auditor init-db

# 2. MinerU 抽取结果入库（需先有 data_md/manifest/index.jsonl）
syllabus-auditor prepare mineru

# 3. 或：pdfplumber 直接扫描 PDF 入库
syllabus-auditor prepare courses --input data_pdf

# 4. 导入课程库 Excel
syllabus-auditor prepare course-library --term 2026-spring

# 5. 批量审核（默认每 PDF 取最新抽取记录）
syllabus-auditor audit run --limit 20

# 6. 生成数据质量报告
syllabus-auditor report quality
```

旧命令（`prepare-courses`、`run-batch` 等）仍保留为 hidden 兼容入口，请改用上述子命令。

## 十、配置说明

| 位置 | 内容 |
|------|------|
| `project.yaml` | `llms`、路径、loader、正则、fusion_scoring、ocr_quality、warning_severity、audit_messages、content_layout_rules 等 |
| `shared/config/schema.py` | 字段映射、章节标题、审核维度模板（低频变更） |
